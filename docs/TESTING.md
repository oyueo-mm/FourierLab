# 테스트

수학 엔진 테스트(Vitest, Node)와 UI 테스트(실제 브라우저, puppeteer-core)를 분리해 두었습니다.

```bash
npm run typecheck   # TypeScript 검사
npm test            # 단위 테스트 (Vitest)
npm run build       # 프로덕션 빌드
npm run e2e         # dist를 /FourierLab/ 하위 경로로 서빙하고 실제 브라우저로 검사
npm run e2e -- --url https://oyueo-mm.github.io/FourierLab/   # 배포된 사이트 검사
```

e2e에는 Chrome/Chromium/Edge 실행 파일이 필요합니다. 일반적인 설치 경로에서 자동으로 찾고, 그 밖의 위치라면 `CHROME_PATH`로 지정합니다. GitHub Actions에서는 배포 전에 위 단계를 모두 실행하며, 하나라도 실패하면 배포하지 않습니다.

### 예제 재구성 검증 (단위 테스트)

- **원**: 진폭 1위가 k = +1이고 반지름이 0.7(소수 4자리)입니다. K = 1일 때 RMSE < 10⁻⁴입니다(360각형이라 남는 잔차).
- **타원**: 진폭 1, 2위가 {+1, −1}입니다.
- **하트, 별**: K = 10 → 50 → 100으로 갈수록 상대 RMSE가 줄고, K = 100에서 1% 미만입니다(저주파 순서).
- **나선**: 같은 K = 100에서 열린 경로의 오차가 닫힌 경로보다 큽니다.

## 실제 브라우저 테스트 — 54개 검사 모두 통과

마지막 실행: 2026-10-20, Microsoft Edge 155.0.4283.62 헤드리스(puppeteer-core 25.15.0), Windows 11. 정적 서버로 `dist`를 `/FourierLab/` 하위 경로에만 제공했습니다(GitHub Pages와 같은 조건, SPA 폴백 없음).

데스크톱(1440×1000) 시나리오:

1. 첫 방문 시 하트 예제를 재생하고 캔버스가 칠해져 있는지(검은 화면 아님, 배경 흰색) 확인
2. 원 예제를 불러오면 재구성 후 처음부터 재생되고, 0.7초 동안 펜 끝이 86.7px 이동(회전 확인)
3. 원 개수 1/10/50/100 적용, 원은 K = 1에서 상대 RMSE 1.14×10⁻⁵
4. 하트의 상대 RMSE가 K = 1 → 10 → 50 → 100에서 23.3% → 2.84% → 0.245% → 0.0839%로 감소
5. **화면에 그려진 펜 끝과 수학 함수 ẑ(t)의 화면 좌표 차이 0.00px**, 해당 픽셀이 펜 끝 색(장미색)
6. 일시정지하면 시간이 멈춤, 타임라인 0.75 → 0.25로 앞뒤 탐색 시 정확한 위치, 한 단계 = 1/N
7. 속도 슬라이더 2× → 실측 진행률 0.200/s(기대값 0.2/s)
8. 선택 방식 전환, 원 표시 토글
9. 캔버스에서 원을 클릭하면 k = +1 성분 카드(반시계 방향) 표시
10. 확대 버튼·휠 확대/축소·드래그 이동·원점 복귀
11. 전체 초기화
12. 클릭 한 번(점 하나)과 아주 짧은 선은 오류 메시지와 함께 거부되고 기존 분석은 유지
13. **마우스로 하트를 그린 뒤 재구성**: 좌표 228개 수집, K = 64에서 상대 RMSE 0.162%
14. 실행 취소/다시 실행
15. PNG 내보내기: 현재 화면(캔버스 크기 986×638), 재구성 결과(1600×1600), 둘 다 올바른 PNG 시그니처
16. JSON 저장 → 다른 상태로 바꾼 뒤 불러오기 → 같은 K, 같은 RMSE(1.7255×10⁻²) 복원. 범위를 벗어난 파일은 이유와 함께 거부
17. **새로고침**하면 자동 저장으로 그림과 설정이 복원되고 캔버스도 정상적으로 그려짐
18. 스펙트럼·오차 차트 렌더링, K 변경 후 차트 수치가 애니메이션 수치와 일치
19. 전체 과정에서 콘솔 오류, 실패한 요청, HTTP 4xx/5xx 없음

모바일 뷰포트(390×844, DPR 2, 터치 에뮬레이션):

- 가로 넘침 0px, DPR 2 캔버스 정상 표시, 그리기 → 애니메이션 → 컨트롤 순서
- 에뮬레이션된 터치로 획 입력 시 좌표 31개가 수집되고 페이지는 스크롤되지 않음

### 아직 검증하지 않은 것

- **실제 터치 기기(스마트폰·태블릿)와 스타일러스로는 테스트하지 않았습니다.** 모바일 결과는 Chromium의 터치 에뮬레이션 기준입니다. 따라서 모바일 사용성 검증이 끝났다고 보지 않습니다.
- Firefox와 Safari에서는 테스트하지 않았습니다(Chromium 계열 Edge만 확인).
- 시각 품질은 자동 검사 외에 스크린샷으로 직접 확인했습니다(`docs/images/`).
