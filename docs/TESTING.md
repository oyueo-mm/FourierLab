# 테스트

수학 엔진 테스트(Vitest, Node)와 UI 테스트(실제 브라우저, puppeteer-core)를 분리해 두었습니다.

```bash
npm run typecheck   # TypeScript 검사
npm test            # 단위 테스트 (Vitest)
npm run build       # 프로덕션 빌드
npm run e2e         # dist를 /FourierLab/ 하위 경로로 서빙하고 실제 브라우저로 검사
npm run e2e -- --url https://oyueo-mm.github.io/FourierLab/   # 배포된 사이트 검사
```

e2e에는 Chrome/Chromium/Edge 실행 파일이 필요합니다. 일반적인 설치 경로에서 자동으로 찾고, 그 밖의 위치라면 `CHROME_PATH`로 지정합니다. GitHub Actions에서는 배포 전에 위 단계를 모두 실행하며, 하나라도 실패하면 배포하지 않습니다.

## 실제 브라우저 테스트 — 170개 검사 모두 통과

마지막 실행: 2026-10-21, Microsoft Edge 155.0.4283.62 헤드리스(puppeteer-core 25.15.0), Windows 11. 정적 서버로 `dist`를 `/FourierLab/` 하위 경로에만 제공했습니다(GitHub Pages와 같은 조건, SPA 폴백 없음). 헬퍼는 `e2e/helpers.mjs`에 있으며 멀티터치는 DevTools 프로토콜의 `Input.dispatchTouchEvent`로 보냅니다.

### 데스크톱 1440×900

**초기 화면·레이아웃** — 하트 예제 자동 재생, 캔버스가 칠해져 있고 흰 배경, 왼쪽 고정 패널 없음(드로어는 숨김·`inert`), 메인 캔버스가 화면 너비의 95% 이상(1393×600px)·높이 560px 이상, 컨트롤이 첫 화면 안, 수학적 분석은 접혀 있고 차트를 그리지 않음.

**원 개수 변경 → 처음부터** (명세 8.1의 항목 전부)
1. 재생 중 변경 → t < 0.05, 계속 재생, 재시작 +1
2. 원 개수·사용 성분 수·RMSE 갱신, 타임라인 슬라이더 0으로 복귀
3. 일시정지 중 변경 → t = 0, 정지 유지, 시간 표시 `t = 0.000`
4. **이전 궤적 잔상 없음**: 변경 전 궤적 픽셀 > 200개 → 변경 후 0개
5. t = 0에서 펜 끝이 새 설정의 시작점에 있음, 재생하면 0부터 진행
6. 한 번 재생이 끝난 상태(t = 1, 정지)에서 변경 → t = 0, 정지, 재생하면 처음부터
7. 빠른 선택 1/2/5/10/50/100/전체 일곱 개 모두 즉시 적용 + t = 0
8. **슬라이더 드래그(마우스)**: 드래그 중 K가 8단계 변하는 동안 재시작 0회·FFT 0회, 손을 떼면 **재시작 정확히 +1회**, t ≈ 0, 마지막 값 유지
9. 키보드(화살표)로 슬라이더 조작 → 키 입력마다 확정·재시작, 숫자 입력 + Enter, **포커스만 이동하면 재시작 안 함**, 성분 선택 방식 변경도 재시작
10. 표시 토글·속도·반복·분석 패널·확대는 재생 위치를 초기화하지 않음
11. 위 모든 조작 후에도 **FFT 실행 횟수 불변**(`counters.spectrum`)

**수학·렌더링 일치** — 원 예제 K = 1에서 상대 RMSE 1.14×10⁻⁵, 하트 K = 1 → 10 → 50 → 100에서 23.3% → 2.84% → 0.245% → 0.0839%(이전 릴리스와 동일), **화면에 그려진 펜 끝과 ẑ(t)의 화면 좌표 차이 0.00px**, 펜 끝 픽셀이 장미색, 일시정지 후 시간 정지, 타임라인 앞뒤 탐색, 한 단계 = 1/N, 2× 속도 실측 0.200/s, Space 키 재생 토글.

**그림 편집 드로어**
- 「그림 편집」 버튼으로 열림, 포커스가 드로어 안으로 이동, 뒤쪽 화면 `inert`
- 드로어 너비 576px, 그림 캔버스 544×544(정사각형, 드로어 안), 「편집 완료」 버튼이 첫 화면 안
- **열어도 메인 캔버스가 리사이즈되지 않고, FFT·시간·재생 상태·재시작 횟수가 그대로**
- 별을 그리면 적용 전 상태(`pending`)로 저장되고 메인은 그대로, 실행 취소·다시 실행
- Esc로 닫힘, 포커스가 「그림 편집」 버튼으로 복귀, 헤더에 표시점, **닫기만 해서는 그림이 지워지거나 적용되지 않음**
- 닫힌 드로어는 직접 포커스를 줘도, Tab을 60번 눌러도 도달하지 못함
- 다시 열면 편집하던 그림 복원, **Tab 40번 눌러도 포커스가 밖으로 나가지 않음**, Shift+Tab 순환, 다시 열면 본문이 맨 위부터 시작
- 경로 모드는 편집 중 그림에만 적용(적용 전 메인 불변), 설명 문구 갱신
- 점 하나·아주 짧은 선·빈 그림은 이유와 함께 거부(드로어 유지)
- 「편집 완료 · 재구성」: 새 그림 분석, 드로어 닫힘, t = 0에서 재생, **FFT 정확히 1회**, 모드 함께 적용, 화면 맞춤 수행, 마우스로 그린 하트가 K = 33에서 상대 오차 0.084%(기준 3% 미만)
- 「재구성 다시 시작」: 적용하되 드로어는 열린 채, 열린 경로 모드 적용
- 예제 선택은 즉시 적용, 배경 클릭으로 닫힘
- 확대 상태는 드로어 열고 닫기·원 개수 변경에 영향받지 않음

**분석·저장** — 분석 패널을 열면 스펙트럼 차트(재생 상태 불변), 원 개수와 오차 차트의 RMSE가 애니메이션 값과 일치, 수학 원리 설명, 휠 확대·드래그 이동·화면 맞춤·원점 복귀, 원 클릭 선택(k = +1, 반시계), PNG 3종(현재 화면 = 캔버스 크기, 재구성·원본 = 1600×1600), JSON 저장·불러오기(같은 RMSE, 불러온 직후 재생), 잘못된 파일 거부 토스트, **새로고침 후 적용한 그림·설정과 적용하지 않은 편집 중인 그림 복원**.

### `prefers-reduced-motion`
자동 재생하지 않고 첫 프레임을 보여 주며, 드로어가 전환 없이 열립니다.

### 뷰포트 6종 — 360×800, 390×844, 430×932, 768×1024, 1280×720, 1440×900
각 뷰포트에서: 가로 스크롤 없음, 재생 버튼·원 개수 슬라이더·빠른 선택이 첫 화면 안, 캔버스가 그려져 있음, 드로어가 화면 안에 들어오고(모바일 전체 화면, 태블릿·데스크톱 576px) 그림 캔버스와 「편집 완료」 버튼이 잘리지 않으며 드로어 내부 가로 넘침 없음. (측정한 캔버스 크기는 [PERFORMANCE.md](PERFORMANCE.md) 참고)

### 모바일 터치 390×844 (DPR 2, 터치 에뮬레이션 + 실제 멀티터치 이벤트)
- 첫 화면에 편집기가 열려 있지 않음, 메인 캔버스 높이 ≥ 380px
- **터치 대상 크기 ≥ 44px**: 재생 56px, 처음으로·이전·다음·다시 시작, 빠른 선택 버튼, 그림 편집, 더보기 메뉴, 확대 버튼, 「속도·성분 선택·표시 옵션」 펼치기, 원 슬라이더·타임라인 높이
- 속도 슬라이더는 접혀 있다가 펼치면 보임
- **터치로 슬라이더 드래그**: 드래그 중 미리보기만(재시작 0회), 손가락을 떼면 재시작 +1, 페이지는 스크롤되지 않음
- 빠른 선택 터치, **두 손가락 핀치로 확대(×1.8 이상)·축소(×0.6 이하)**, 한 손가락 드래그로 화면 이동(페이지 스크롤 없음, 재생 불변)
- 컨트롤 영역을 위로 쓸면 페이지가 세로 스크롤됨(`touch-action` 범위 확인)
- 터치로 드로어 열기(전체 화면 390×844, 그림 캔버스 ≥ 340px), 열려 있는 동안 본문 스크롤 잠금, 터치로 선 그리기(페이지 스크롤 없음), 입력 취소(`touchCancel`)는 안내하고 기존 그림 유지, 터치로 「편집 완료」, 닫으면 스크롤 잠금 해제
- 화면 회전(844×390 ↔ 390×844): 가로 스크롤 없음, 캔버스가 비지 않음

### 전체
콘솔 오류·실패한 요청·HTTP 4xx/5xx가 한 건도 없음.

### 테스트로 발견해 고친 문제
- 원 개수 입력칸에 포커스가 있을 때 다른 곳(드로어 열기 등)으로 포커스가 옮겨가면, 값이 같아도 확정 처리되어 애니메이션이 재시작되었습니다.
- 드로어를 닫았다 다시 열면 이전 스크롤 위치가 남아 그림 캔버스가 가려질 수 있었습니다.
- 모바일에서 빠른 선택 버튼이 줄바꿈되어 캔버스가 줄어들었습니다.

### 아직 검증하지 않은 것
- **실제 터치 기기(스마트폰·태블릿)와 스타일러스로는 테스트하지 않았습니다.** 모바일 결과는 Chromium의 터치 에뮬레이션과 DevTools로 보낸 멀티터치 이벤트 기준입니다. 실제 기기의 주소창 높이 변화(`dvh`), 가상 키보드, iOS Safari의 핀치·`touch-action` 처리, 시스템 제스처 영역은 확인하지 못했습니다. 따라서 모바일 사용성 검증이 끝났다고 보지 않습니다.
- Firefox와 Safari에서는 테스트하지 않았습니다(Chromium 계열 Edge만 확인).
- 시각 품질은 자동 검사 외에 스크린샷으로 직접 확인했습니다(`docs/images/`).
