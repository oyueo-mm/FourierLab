# FourierLab 구조

백엔드 없이 모든 계산과 렌더링이 브라우저에서 이루어지는 단일 페이지 앱입니다(React 19, TypeScript, Vite, Tailwind CSS 4, Canvas 2D, Recharts).

## 디렉터리

```

    complex.ts     복소수 연산 (참조용·테스트용)
```

## 화면 구조

```
┌ Header: FourierLab · [그림 편집] · PNG · 저장 · 불러오기 · 원리 (모바일: 편집 + ⋯ 메뉴) ┐
├ Stage (min-height: 100dvh − 헤더) ─────────────────────────────────────────────┤
│  Visualizer (flex: 1, 최소 300px)                                               │
│  ControlsDock  ─ 데스크톱: 3열 / 모바일: 1열 + 「더보기」 접이식                    │
├ 수학적 분석 (접힘이 기본) · 고급 설정 (접힘이 기본) ──────────────────────────────┤
└ EditDrawer (fixed, 닫힘 = visibility:hidden + inert) ──────────────────────────┘
```

- Stage는 `min-h-[calc(100dvh-3.5rem)]`인 세로 flex입니다. 캔버스가 남는 높이를 모두 차지하므로 화면 높이가 달라도 컨트롤이 첫 화면 안에 들어옵니다. `dvh`와 `env(safe-area-inset-*)`로 모바일 브라우저 주소창 변화와 노치를 반영합니다.
- ControlsDock의 「더보기」 그룹은 `display: contents`를 써서 데스크톱(lg+)에서는 3열 그리드의 칸으로 바로 배치되고, 모바일에서는 접힌 영역이 됩니다. DOM은 하나이므로 컴포넌트를 두 벌 만들지 않습니다.
- 슬라이더는 `pointer: coarse` 또는 폭 640px 미만에서 44px 높이와 28px 손잡이를 사용합니다.

## 데이터 흐름

```
EditDrawer ──(획: 수학 좌표)──► history[] (실행 취소/다시 실행, 항목 = {points, source, mode})
                                   │  「편집 완료·재구성」 / 「재구성 다시 시작」 / 예제 선택 / 「편집한 그림 적용」
                                   ▼  analyze(): 검증 → analyzed 갱신 + settings.pathMode + player.restart() + play()
analyzed 경로 + settings ──► useAnalysis
   preparePath(경로, 모드, N)         ← 경로·모드·N이 바뀔 때만
   computeSpectrum (FFT)              ← 위와 같음
   rankComponents ×2, errorCurve ×2   ← 위와 같음
   selectComponents(K, 선택, 연결순서) ← K·방식이 바뀔 때 (FFT 재계산 없음)
   compileChain, evaluateSeries(역 FFT)
                                   ▼
SceneData ──► Visualizer (정적 캔버스 + 동적 캔버스)
Player ──(매 프레임 t)──► 동적 레이어만 다시 그림
```

- **편집 중인 그림과 적용된 그림을 분리**합니다. `history`의 현재 항목이 드로어에서 편집하는 그림이고, `analyzed`가 애니메이션이 보여 주는 그림입니다. 둘이 다르면 `pending`이며, 드로어를 열고 닫는 것만으로는 `analyzed`가 바뀌지 않으므로 FFT도 실행되지 않습니다(브라우저 테스트가 `counters.spectrum`으로 확인).
- **경로 처리 방식은 그림 항목의 일부**입니다. 드로어에서 모드를 바꿔도 「적용」하기 전에는 메인 화면의 분석이 바뀌지 않습니다.
- **계산과 렌더링 분리**: FFT는 입력 경로·경로 처리 방식·샘플 수가 바뀔 때만 실행합니다. 원 개수나 선택 방식을 바꾸면 이미 계산한 계수 배열을 다시 정렬하고 자르기만 합니다.
- **React와 애니메이션 분리**: `Player`는 React 바깥의 클래스입니다. 매 프레임 `onFrame` 구독자(캔버스 그리기, 타임라인·시간 표시·성분 카드의 현재 각도)가 DOM이나 캔버스를 직접 갱신하므로, 재생 중에는 React 재렌더링이 일어나지 않습니다.
- **차트 우선순위**: 스펙트럼·오차 차트는 분석 패널을 열었을 때만 그리고, `memo`와 `useDeferredValue`로 지연된 K를 받습니다. 슬라이더를 움직이면 애니메이션이 먼저 갱신되고 차트는 뒤따라 갱신됩니다.

## 원 개수 변경과 재시작

`Player.restart()`는 시간을 0으로 되돌리면서 **재생 상태는 유지**합니다.

| 상태 | restart() 후 |
|---|---|
| 재생 중 | t = 0에서 계속 재생 (직전 프레임 시각을 버려 시간이 튀지 않음) |
| 일시정지 | t = 0, 일시정지 유지, 처음 프레임을 그림 |
| 한 번 재생 완료(t = 1) | t = 0, 완료 상태 해제, 일시정지. 재생하면 처음부터 진행 |

재시작이 일어나는 곳: 원 개수 확정, 성분 선택 방식 변경, 샘플 수 변경, 새 그림 적용·예제 선택·프로젝트 불러오기, 「처음부터 다시 재생」 버튼. 재시작하지 않는 곳: 표시 토글, 연결 순서, 속도, 반복, 확대·이동, 분석 패널.

슬라이더(`ui.tsx`의 `Slider`)는 두 콜백을 가집니다.

- `onChange`: 손잡이가 움직이는 동안 모든 값을 전달합니다(미리보기: 원 개수·RMSE가 바뀌고 애니메이션은 계속 진행).
- `onCommit`: 포인터 드래그가 끝날 때(`pointerup`/`pointercancel`, 창 전체에서 감지하므로 손잡이 밖에서 놓아도 됨) **한 번만** 호출합니다. 포인터를 쓰지 않는 변경(키보드, 보조 기술)은 즉시 확정합니다.

원 개수 슬라이더는 로그 눈금이라 값→위치 변환이 정확한 역함수가 아닙니다. 그래서 손잡이 위치는 슬라이더가 따로 보관해, 드래그 중 손가락 아래에서 손잡이가 흔들리지 않게 합니다.

숫자 입력칸은 Enter를 명시적 확정(같은 값이어도 재시작), 포커스 이탈은 값이 바뀐 경우에만 확정으로 처리합니다. (포커스만 옮겨도 재시작하던 문제를 브라우저 테스트로 발견해 고쳤습니다. 예: 입력칸에 포커스가 있는 채 드로어를 열면 포커스가 이동하며 재시작이 일어났습니다.)

## 그림 편집 드로어

- **모달**: `role="dialog" aria-modal`. 열면 닫기 버튼으로 포커스가 이동하고, Tab/Shift+Tab은 드로어 안에서 순환하며, Esc로 닫고, 닫으면 「그림 편집」 버튼(열 때 포커스가 있던 요소)으로 포커스가 돌아옵니다. 열려 있는 동안 뒤쪽 화면은 `inert`이고 본문 스크롤은 잠깁니다(`scrollbar-gutter: stable`이라 폭이 변하지 않음).
- **닫힌 상태**: `visibility: hidden` + `inert`로 포커스를 받지 않지만 레이아웃은 유지됩니다. 그래서 그림 캔버스가 크기를 유지하고, 열 때 캔버스가 리사이즈되거나 비어 보이지 않습니다. 열 때는 즉시 보이고(포커스 이동을 위해), 닫을 때만 슬라이드 애니메이션 동안 보입니다. `prefers-reduced-motion`이면 전환 없이 열고 닫습니다.
- **크기**: 폭 `min(36rem, 100vw)`(데스크톱 576px), 640px 미만은 전체 화면. 그림 캔버스는 `min(100%, max(18rem, 100dvh − 16rem))`인 정사각형입니다. 내용이 길면 본문만 스크롤하고 하단 「편집 완료」 버튼은 고정됩니다. 열 때마다 본문 스크롤을 맨 위로 되돌립니다.
- **좌표**: 획은 수학 좌표(y 위쪽, 짧은 변이 [−1, 1])로 저장하므로 드로어와 메인 캔버스 크기가 달라도 모양이 변하지 않습니다.

## 재생 시계

- 진행도 p ∈ [0, 1]이며, dp/dt = speed / 10초입니다. 1×에서 그림 한 바퀴가 10초입니다.
- requestAnimationFrame의 실제 타임스탬프 차이를 사용합니다. 한 프레임의 최대 진행은 0.1초로 제한하고, `visibilitychange` 이벤트 때 기준 시각을 초기화합니다.
- 정지 상태에서는 rAF 루프가 없습니다. 데이터나 뷰가 바뀌면 한 번만 다시 그립니다.

## Canvas 렌더링과 제스처

- 두 캔버스를 겹쳐 사용합니다. 정적 레이어(배경, 격자, 원본, 전체 근사 곡선)와 동적 레이어(궤적, 원, 벡터, 펜 끝, 선택 강조)입니다.
- devicePixelRatio(최대 3)를 반영해 버퍼 크기를 정합니다. ResizeObserver 콜백 안에서 크기를 바꾸는 즉시 다시 그리므로 빈 화면이 보이지 않습니다.
- **자동 맞춤**: 새 그림을 적용하면 곡선·원본·가장 큰 원이 들어오도록 캔버스에 맞춥니다. 오른쪽의 확대 버튼 열과 겹치지 않도록 오른쪽에 여백(최대 56px)을 둡니다. 캔버스가 아직 크기를 갖기 전에 요청된 맞춤은 첫 크기 확정 때 수행합니다. 사용자가 확대·이동한 뷰는 원 개수 변경, 드로어 열고 닫기, 분석 패널 열기로 바뀌지 않습니다.
- **Pointer Events 제스처**: 포인터 하나는 드래그 이동(5px 이상 움직이면), 움직임 없이 놓으면 원 선택(링·팔까지 8px 이내). 포인터 둘은 핀치 확대·축소(두 점 중점 기준)와 중점 이동. 휠은 커서 기준 확대. 끝점 따라가기 중에는 화면 중심 기준으로 확대합니다.
- **touch-action 정책**: 시각화 캔버스와 그림 입력 캔버스만 `touch-action: none`입니다. 그 밖의 모든 영역(헤더, 컨트롤 도크, 분석 패널)은 정상적으로 스크롤됩니다. 시각화 캔버스에서는 한 손가락 드래그가 화면 이동이므로 그 위에서 시작한 스와이프는 페이지를 스크롤하지 않습니다.
- 펜 끝은 `evaluateChain`의 마지막 관절입니다. 단위 테스트와 브라우저 테스트로 화면의 펜 끝이 수학 함수 ẑ(t)와 일치함을 확인합니다.

## 그림 입력

- Pointer Events 하나로 마우스·터치·펜을 처리합니다. `setPointerCapture`로 캔버스 밖으로 나가도 획이 이어지게 하고, 지원되는 브라우저에서는 `getCoalescedEvents`로 빠른 드래그의 중간 좌표까지 받습니다. 한 번에 한 포인터의 획만 받아 두 번째 손가락이 닿아도 선이 꼬이지 않습니다.
- `pointercancel`이 오면 그리던 획을 버리고 안내합니다. 좌표가 20 000개에 이르면 그 지점에서 획을 끝내고 경고를 표시합니다.

## 저장

- 프로젝트 JSON 형식은 `{ format: "fourierlab-project", version: 1, savedAt, source, path: [[x, y], …], settings }`입니다. 좌표는 10⁻⁶ 단위로 반올림합니다.
- 불러올 때는 `JSON.parse`만 사용하고 코드는 실행하지 않습니다. 모든 필드의 타입, 열거값, 숫자 범위, 배열 길이, 색상 형식(#rrggbb)을 검증하고, 실패하면 이유를 한국어로 표시합니다.
- 자동 저장은 같은 형식의 프로젝트에 **적용되지 않은 편집 중인 획과 그 경로 모드**를 더해 localStorage에 저장합니다. 첫 릴리스의 형식(편집 중인 획이 점 배열)도 읽습니다. 저장소에 접근할 수 없거나 데이터가 손상됐으면 조용히 기본값을 사용합니다.
